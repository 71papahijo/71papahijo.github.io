FPGA Snake Game

This project recreates Snake entirely in FPGA hardware, using a finite state machine to control game flow, VGA output to draw the board, and switch-based input for movement.

The design balances gameplay features with FPGA resource limits, requiring tradeoffs in grid size, apple generation, and snake length.

Project Architecture

The design is organized as a modular FPGA system. A top-level module connects the movement logic, game-state control, apple generation, and VGA rendering pipeline into one coordinated design.

This architecture made the project easier to build and debug because each subsystem had a clear role. Input handling controls the snake direction, the FSM governs the overall game flow, apple logic controls placement behavior, and the VGA module maps the game state onto the display output.

Structuring the project this way also made it easier to refine individual pieces without redesigning everything at once, which is especially important in hardware projects where logic usage and timing constraints can quickly grow.

FSM States

The finite state machine controls when the system is waiting, when the game is actively running, and when the game has reached a finished condition. Two important visible states are idle and end.

Idle State

The idle state is the controlled starting point of the game. In this state, the system holds the initial setup, prevents unintended movement, and waits for valid player input before transitioning into active gameplay.

  • Sets a clean starting condition for the snake.
  • Waits for player input before movement begins.
  • Provides a stable transition into the running state.

End State

The end state is reached once a finishing condition occurs. At that point, gameplay no longer updates normally, and the FSM holds the game in a final display state so the result is visible and stable.

  • Stops normal gameplay updates after the game ends.
  • Shows a clear final condition to the player.
  • Creates a reliable point for reset or restart.

Resource Constraints

One of the biggest challenges in the project was fitting the game logic into the available FPGA logic budget.

Earlier versions of the design exceeded the available logic resources, which forced tradeoffs in the final implementation. The board representation had to be reduced, the snake length had to be capped, and apple generation had to move toward a more deterministic FSM-based approach.

These constraints shaped the final architecture. Instead of maximizing features first, the design had to prioritize fitting within the FPGA while still preserving stable gameplay and clear state behavior.

  • Reduced grid size to lower logic usage.
  • Limited maximum snake length.
  • Simplified apple generation logic.
  • Focused on stable gameplay over extra features.
